## Standalone Android launch regression

The previously distributed APK from run 42872149942 was installed and launched without IDE fast deployment on an Android 11 x86_64 emulator in [diagnostic run 42970667739](https://github.com/godrich-hk/netconnect/actions/runs/42970667739). It exited immediately with SIGABRT and inspection found no embedded managed assemblies. A standalone APK must embed assemblies instead of depending on IDE fast deployment. The project now sets `EmbedAssembliesIntoApk=true` for Android and the installer workflow checks both the assembly bundle and ARM64 native libraries, installs the new APK on an Android 11 emulator, launches it, and checks the resumed activity and process. A passing emulator test does not prove operation on a Redmi Note 8 Pro or test transfers between devices. Debug signing keys can differ between CI runs: uninstalling an older install may be required, and uninstalling deletes private app data.

The `ec07a44` Android APK published in [run 42971018664](https://github.com/godrich-hk/netconnect/actions/runs/42971018664) passed the independent Android 11 x86_64 install-and-launch smoke test in [run 42971892391](https://github.com/godrich-hk/netconnect/actions/runs/42971892391). Its ARM64 libraries and embedded `.dll.so` files were observed in APK inspection. The first automated assembly check incorrectly treated the `.dll.so` packaging format as absent; the checker was updated. This does not test a physical ARM64 device or any transfer scenario.

Final verification for commit `13d116d`: [installer run 42972183724](https://github.com/godrich-hk/netconnect/actions/runs/42972183724) passed Android APK publish, ARM64/assembly content verification, and install/launch on an Android 11 x86_64 emulator; Windows publish and installer build also passed. [Core run 42972183773](https://github.com/godrich-hk/netconnect/actions/runs/42972183773) passed. No physical Redmi test or end-to-end transfer test was performed.
